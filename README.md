# LAIM assessor agent

Судья оценивает итоговую КМ по подтверждённой рубрике v3. Формула первичных человеческих оценок служит расчёту baseline; судья не имитирует голоса разметчиков и не переопределяет эту формулу.

## Входы и смысл оценки

`reference_umr` содержит первичную разметку `main_metric`, `dataset_role=reference` и точный `definition_id`. `monitoring_umr` содержит наблюдения конвертера/выборки с `dataset_role=monitoring`, тем же определением и `evaluation_ready=True`. При несовпадении происхождения запуск прекращается до LLM.

`monitoring_metric` задаёт единицу оценки, рубрику, дискретный `score_values`, направление качества, границу дефекта и обязательные свидетельства. Домен structured output задаётся определением, даже если некоторого класса нет в RAG. Текст ответа и наблюдаемый маршрут передаются отдельно; для dialogue сохраняются наблюдения каждого turn.

Отсутствие обязательных данных не является правильным ответом. Судья может вернуть `not_assessable`; наружу это выходит как отсутствующая оценка и учитываемый отказ. Удалены правило автоматического зачёта непроверяемых фактов и повторный проход, который пересматривал только сниженные оценки в сторону зачёта.

## Калибровка и назначения прогонов

- `combined` — калибровка и мониторинг одним экземпляром судьи.
- `scoring` — reference holdout; `assessment_result.purpose=calibration`, такие оценки не принимаются как текущая КМ.
- `monitoring` — разметка без калибровки в этом вызове; сама по себе не даёт допуска KM/global drift.

Разделение train/holdout сохраняет переданные группы сессий. После разделения из RAG удаляются целиком train-группы, содержащие точный дубликат assessment_context из holdout; при отсутствии групп удаляются совпадающие train-единицы. Holdout не меняется. При опустевшем train калибровка отклоняется. Проверка ловит точные структурные дубликаты, но не перефразировки. Калибровка публикует совпадение оценок, каппу, альфу, корреляцию, полноту/точность на дефектах, смещение и достаточность holdout. Дефект определяется утверждённым порогом и направлением, а не минимальным наблюдённым значением.

Калибровка различает полный `holdout_units` и `paired_units` с ответом судьи.
`acc_auto`, baseline по моде, nominal κ/α, Спирман и `mean_absolute_error`
считаются по сопоставленным парам; `agreement_scope=paired_units`,
`agreement_scale=nominal`. Альфа сравнивает судью с итоговой оценкой единицы КМ,
а не с исходной панелью людей. Для панели нужны отдельные голоса разметчиков.

`coverage`, `defect_coverage` и `nondefect_coverage` показывают доступность судьи.
`defect_recall` имеет знаменателем **все** человеческие дефекты holdout: отказ
не считается обнаруженным дефектом. `defect_confusion` отдельно сохраняет TP,
FN, FP, TN и отказы на обоих классах. Таким образом, отказ на трудных примерах
не повышает полноту. Низкий recall сам по себе даёт red/insufficient_defect_recall,
даже при высоком согласии на оставшихся ответах. Проверка минимального объёма
использует число сопоставленных пар. При отсутствии дефектов recall=null;
без срабатываний precision=null; постоянные оценки дают неопределённую
корреляцию, а общая единственная метка — неопределённые κ/α (null).

Каждая строка этих диагностик — одна единица оценки с одинаковым весом.
Метрики не являются взвешенной оценкой качества всего периода и не дают
доверительной границы допуска. Старые классы без состояния для парсинга и
усреднения разных критериев удалены: v3 оценивает один итоговый assessment_score.

`scored_data` сохраняет provenance и итоговый `main_metric`. `assessment_result` имеет версию v2, `definition_id`, назначение и `run_id`; строки связаны с ним через `assessment_run_id`. Потребители не могут подставить допуск другого запуска.

## Ограничения

Положительная калибровка на первичной корзине не доказывает переносимость судьи на любое будущее распределение. Интервалы смещения, способ разбиения и требования к текущей ручной проверке остаются предметом статистического этапа исследования. Нагрузочная приёмка на сотне агентов и живые модельные прогоны после изменения промпта ещё обязательны.

Вспомогательный `domain_rag_files_zip` не заменяет отсутствующие факты конкретного обращения. Контент архива и конфигурацию модели необходимо фиксировать в развёртывании; их полная версия пока не входит в definition_id.

## Развёртывание

Python 3.12, все исходники в descriptor. Удалён отдельный вход инструкции: действует рубрика определения. Переписывание рубрики LLM во время регулярного прогона отключено. Остальные настройки модели, размера train/holdout и допуска перечислены в descriptor.

```bash
python3 -m pytest -q
ruff check .
```

Поиск few-shot сохраняет полный контекст вместе с его оценкой. BM25 преобразуется в ранги документов с одинаковыми рангами для ties; перестановка корзины не меняет их релевантность. Векторный и BM25 пути объединяют один полный пример. Обрезка примера с сохранением gold полного диалога недопустима; для ограничения контекста нужен бюджет целых примеров. Эти исправления не доказывают качество судьи на новой рубрике.

При отсутствии доменных документов контекст знаний пуст. Судье не предлагается заменять недоступные актуальные или клиентские факты собственными знаниями; недостаточность свидетельств остаётся основанием для not_assessable.

Объявленная evaluation.prediction_observable передаётся судье независимо от метода вычисления человеческой КМ: route_label читается из scenario, output_answer — из ответа. Для accuracy сохраняется выделенная prediction-колонка. Наличие проверяется на каждой реплике reference и monitoring; пропавший маршрут диалога не заменяется первым значением. Связь scenario с наблюдённой категорией должна быть задана утверждённым layout.

### Достаточность калибровки

Точные копии `assessment_context` в holdout оцениваются один раз, до LLM-вызовов.
Если один контекст имеет разные человеческие метки, калибровка отклоняется как
противоречивая до построения судьи. `holdout_source_units` сохраняет исходное
число строк; `holdout_units` и метрики относятся к уникальным задачам.
Минимумы поддержки проверяются по разным группам, а не числу turns одной сессии;
`admission_support` показывает эти отдельные счётчики и их область применения.
Это защита от очевидного раздутия проверки копиями и длинными сессиями, а не
доказательство статистической независимости всех оставшихся задач.

Дедупликация касается только калибровочного holdout. Частоты monitoring и
broadcast результатов не меняются. Reference bias остаётся диагностикой этой
калибровки; переносить его на человеческую КМ другого периода нельзя.
